  4. Workera scout, builder, reviewer and so on Always in a team, one responsibility. Decides only how to do its own task. Cannot change the scope or what done means, and sends out no agents.

Where each rank shows up, for example in Many hands

  • Captain: the pilot picks the Many hands team plan and hands out the items.
  • Officer: the team lead of Many hands splits the items and accepts or rejects what comes back.
  • Workers: one builder per item, and a reviewer per item, each reporting to the Officer.

In Build and check, and in the other plans without a team lead, the Captain leads and every role is a Worker. Officers also appear as a runner working alone in a background session, and as the librarian when it runs as a standing session (PR 7). The same agent can be an Officer in one team and a Worker in another.

My proposals, strike any

1. How they address each other (decision D2)

Up the chain by rank. Down the chain, Workers by job, Officers and the Captain by rank. Keep it short. For example:

  • Worker to Officer: "Officer, the build failed because the test needs file X."
  • Officer to Captain: "Captain, item 3 needs a file outside its list. Your call."
  • Captain to Commander: "Commander, one question for you."
  • Captain to Worker: "Builder, build item 3 in these files."

No fixed report line, no numbering, no call signs. Agents inside a workflow just return their results and need no address. A plain claude chat has no ranks.

2. When stuck

Worker to Officer to Captain to Commander. A Worker whose brief is unclear, clashes with your truth, or needs files outside its list stops and says so in one line. It never guesses and never asks you directly. Anything that needs you becomes a question in the workshop's questions.md. A step is skipped only when it is missing (a Worker in a team the Captain leads reports to the Captain).

3. A fallback rank line in each agent's file

Used only if no rank was handed out with the work: the pilot takes Captain, the runner takes Officer, every other agent takes Worker. It is not a name and not an identity. It is there because some agents (for example a pilot you start yourself) have no sender to give them a rank. If you strike it, rank comes only from the team plan or the sender.

How a rank reaches an agent

  • Rank comes from the team plan and from whoever hands out the work. Each plan lists its roles with their rank, and the opening message starts with one line saying it, for example Rank: Worker. Reports to: Captain. You decide: ... You do not decide: .... Then come the workshop's own notes and checks, if the work belongs to a workshop, then "Work outside your brief: report it as a capture line; do not do it."
  • In a build run, the lead is Captain and every other role is a Worker. When you say "go" on a launch (PR 4), your session is Captain and every role in that run is a Worker.
  • Ranks are guidance, not locks: no guard stops a Worker that oversteps. The reviewer checks scope, the file-list check fails a PR that touched files outside its list, and you merge.
