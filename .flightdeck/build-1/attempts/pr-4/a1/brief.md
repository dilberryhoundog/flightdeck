## 1. Purpose

From an active workshop, one owner command, `/flight:launch <workshop>`, reads the workshop, answers "what will tell us the work is right?" from its `verify.md`, picks the smallest team plan that fits and says why in one line (or says "plain chat is enough"), shows a five-line launch card (team plan, seats with ranks and models, agent count, a rough token guess, base branch and attempt branch), waits for the owner's "go", and runs the matching workflow. The Build and check workflow returns a draft pull request with a report whose every line is marked [checked], [reviewed] or [stated]. Every agent in every workflow gets the global rules, its seat's `Rank:` line, the workshop's own context and verification (the scoped block from PR 1's `scope` command), the capture line, then its task, in that order.

PR 4 ships three runnable workflows in the plugin's `workflows/` folder: `build-and-check` (the default team plan, run end to end), `recon` (three scouts, a summary, a claim check) and `second-opinion` (review, adversary and imposter on any file, diff or branch the owner names, then one short summary). The other four team plans (Decide, Spec first, Many hands, Root cause) stay pilot-run from their pages, as the plan says.

Ranks (plan 3.2, 4 "PR 4"): the session that says "go" is the Captain; every seat in these workflows is a Worker (none is a team lead or a long-lived background session). Nothing starts on its own: the launch skill sets `disable-model-invocation: true`, and a workflow run starts only after the owner's "go" (or when the owner types a workflow command himself).

PR 4 ships no workshop folder: a folder means active, and only the owner activates. The owner activates the example entry `demo-attempt-age` as the first step of the try.

## 2. VISION sections served

- Launches: "Multi agent workflows of all shapes, claude picks intelligently to build from the workshop. Scoped and specced work, checkable, reviewed, PR'd, worktrees, dynamic workflows." One command picks the smallest team plan, runs a dynamic workflow with a builder in its own worktree, script checks, review, adversary and imposter, and returns a draft pull request.
- Workshops: the workshop's own context and verification reach every launch agent and no other ("workshop stored verification and context given to agents working in that workshop only"); each launch is one attempt on its own branch `<workshop>-a<k>` that writes only its attempt folder and the files its brief names.
- Roleplay: the Captain says go; every seat carries its `Rank:` line from PR 1's `entry-points.md`.
- Cheap tokens, smart agents: model and effort named per stage (Haiku for scope and checks, Sonnet for building and reading, Opus only for brief, adversary and triage); the launch card shows seats, models and a cost guess before "go".
- Human energy: one "go" instead of many decisions; a report that leads with the try; questions in the `questions.md` format and capture lines filed by the Captain; nothing asks the owner to approve agent-written text.
- Built with quality: one test file that runs every workflow with a stub agent; the part can be removed without breaking anything else.
- Keep it simple: plain chat is unchanged; the launch cannot be started by the model.

Not served by PR 4: Themed HTML page suite (PR 2), Local CLI (skipped by the owner), Manuals and libraries (PR 7), Laboratory (PR 6).

## 5. Shared rules every unit follows

### 5.1 Writing

- Markdown: one paragraph per line, no hard wrapping, plain words, literal and direct, no tables in owner-facing text. Explain any term the owner might not know in a few words the first time (for example "worktree: a separate copy of the repository on its own branch").
- No rank word (commander, captain, officer, worker, any case) in the skill's `name:` or `description:`. Rank words appear in bodies and prompts only.
- No `fable`, `best`, `xhigh` or `max` as a model or effort value anywhere. In the `.js` files, do not write the text `model:` or `effort:` followed by a quoted value other than `haiku`, `sonnet`, `opus` (model) and `low`, `medium`, `high` (effort), not even in comments or prompt strings: PR 1's ceiling guard (`flightdeck/hooks/guard.mjs`, rule `ceiling`) scans the whole script text of a Workflow call, and the hard-rule check scans `.js` files under `flightdeck/`.
- Never call `dw` or `dev-workspace` from a script.
- Node v22, ES modules, Node built-ins only, no `package.json`. Tests run with the quoted glob form: `node --test 'flightdeck/skills/launch/tests/*.test.mjs'` (on Node 22 `node --test <folder>` fails with "Cannot find module").

### 5.2 PR 1 facts this PR builds on (read from `origin/build-1-pr1-basic-a1`)

- `node <plugin root>/lib/workshops.mjs scope <name> --json [--root <dir>]` prints one line of JSON `{"block": "...", "checks": [...], "questions": [...], "warnings": [...]}` and always exits 0. `block` is empty and `warnings` names the reason when the workshop has no folder. The block opens with `Workshop <name>: the following is this workshop's own context and verification, in addition to the global rules. VISION.md and build.txt win on any conflict.` and ends with `Original files: ...`. `checks` are the backticked commands under `## checks` in `verify.md`; `questions` are the `- ` lines under `## questions`. The root defaults to the first folder upward from `CLAUDE_PROJECT_DIR` or the current directory that holds `.flightdeck/`.
- The four ranks are the `- <Rank>:` lines under `## Ranks` in `flightdeck/policies.md`: Commander, Captain, Officer, Worker.
- `flightdeck/skills/team-plans/entry-points.md` has eight seats (`## scout`, `## builder`, `## reviewer`, `## adversary live`, `## adversary cold`, `## imposter`, `## runner`, `## team lead`); each section's first non-empty line is its `Rank:` line, matching `^Rank: (\w+)\. Reports to: .+\. You decide: .+\. You do not decide: .+\.$`.
- `flightdeck/skills/team-plans/SKILL.md` holds, on the line after "A global rules block you can paste:", the global rules block in backticks (quoted in 6.1).
- PR 1's agents: `flight:pilot`, `flight:runner`, `flight:scout` (Read, Grep, Glob), `flight:builder` (Read, Edit, Write, Bash, Grep, Glob), `flight:reviewer` (Read, Grep, Glob, Bash), `flight:adversary` (Read, Grep, Glob only), `flight:imposter` (Read, Grep, Glob, Bash, Edit, Write).
- `ceilingDecision(input, env, readFile)` is exported by `flightdeck/hooks/guard.mjs`; for `{tool_name: 'Workflow', tool_input: {script: <text>}}` it returns `"Owner's ceiling: Opus at high effort"` when the text breaks the ceiling, else `null`.
- The hard-rule check `lab/checks/hard-rules.mjs` already requires `disable-model-invocation: true` in `flightdeck/skills/launch/SKILL.md` once that file exists (case `owner-only-skills`).
- Claude Code facts (plan 3.0, library `workflows.md`): a workflow script has no file or shell access and cannot load modules; `export const meta = {...}` is the first statement, plain literals only, with `name` and `description`, and `phases` titles matching every `phase()` title; the body is plain JavaScript with top-level `await` and a top-level `return`; `Date.now()`, `Math.random()` and a no-argument `new Date()` throw; `args` is a global (a string or an object, `undefined` when omitted); `agent()` resolves to `null` when stopped or on an unrecoverable error; plugin workflows run as `/flight:<meta.name>`. A subagent worktree branches from the default branch, so a launch builder makes its own branch with `git switch -c <branch> <base>`. Git worktrees of one repository share branches, so a branch committed in one worktree is readable from every other with `git show <branch>:<path>`, but a branch can be checked out in only one worktree at a time.

## 6. The workflow contract (u1 writes it, u2 tests it, u3 calls it)

### 6.1 Text constants (identical in all three scripts, written as string literals in each, because a script cannot import)

- `GLOBAL` (verbatim from PR 1's team-plans `SKILL.md`): `Binding documents, read first: .flightdeck/VISION.md, .flightdeck/build.txt and, for a workshop, its constraints.md; the newest lines win. Hard rules: never push to main or master, never force-push, never delete a branch, never merge a pull request, never write the owner's files. Ceiling: nothing above Opus at high effort. Writing: one paragraph per line, plain words.`
- `CAPTURE`: `Work outside your brief: report it as a capture line; do not do it.`
- Seat `Rank:` lines held verbatim from PR 1's `entry-points.md` (the launch test checks they still match the file):
  - `SEAT.scout`: `Rank: Worker. Reports to: whoever sent you (your Officer, or the Captain). You decide: where to look and how to read. You do not decide: the question, its scope or what is done with the answer; you change no files and send out no agents.`
  - `SEAT.builder`: `Rank: Worker. Reports to: whoever sent you (your Officer, or the Captain). You decide: how to build your unit inside your own files. You do not decide: scope, done, verification or truth; you do not accept your own findings and you send out no agents.`
  - `SEAT.reviewer`: `Rank: Worker. Reports to: whoever sent you (your Officer, or the Captain). You decide: which findings to report and how severe each is. You do not decide: whether a finding is accepted, the brief, done or truth; you change no files.`
  - `SEAT.adversary` (the "adversary cold" section): `Rank: Worker. Reports to: whoever sent you (your Officer, or the Captain). You decide: which findings to raise, their severity and confidence, and when to withdraw one. You do not decide: whether a finding is accepted, the criteria or truth; you change no files.`
  - `SEAT.imposter`: `Rank: Worker. Reports to: whoever sent you (your Officer, or the Captain). You decide: how the owner would answer and what confused you. You do not decide: the try steps, done or truth; you write only in your scratch folder and the files the try steps say the owner edits.`
- Seats with no section in `entry-points.md` (Decided here; PR 4 may not add sections to PR 1's file, so the script holds these two lines, each in the same shape):
  - `RANK_TASK` (scope, brief, check, recheck, report, prepare, summary): `Rank: Worker. Reports to: the Captain (the session that started this launch). You decide: how to do this one task. You do not decide: scope, done, verification or truth; you do not accept your own findings and you send out no agents.`
  - `RANK_TRIAGE` (triage): `Rank: Worker. Reports to: the Captain (the session that started this launch). You decide: a recommended accept or reject for each finding, with a one-line reason. You do not decide: scope, done, verification or truth; the Captain may overrule any decision, and you send out no agents.` (Triage recommends; the Captain accepts, as `policies.md` says.)
- `GLOBAL_CHECKS(base)`: `['node lab/checks/hard-rules.mjs --base ' + base, 'claude plugin validate flightdeck']`. Each runs only when its file or folder exists in the worktree (`lab/checks/hard-rules.mjs`, `flightdeck/.claude-plugin/plugin.json`); otherwise it is reported as skipped with "not in this project". (Decided here: these are the plan's global checks, made safe for projects that are not FlightDeck's own repository.)

### 6.2 The opening text

Every `agent()` prompt is built by one function, in this order, separated by blank lines: `GLOBAL`, then the seat's rank line, then the scoped block (only when a workshop is given and the scope stage has run), then `CAPTURE`, then a line starting `Task: ` followed by the task. No other line in a prompt starts with `Rank: `, and no other line starts with `Task: `. The scope agent's own prompt has no block (it is the one fetching it).

### 6.3 Common shape of each script

- First line of the file exactly `export const meta = {`; the meta object holds only literals: `name`, `description` (one sentence), `phases: [{ title: '...' }, ...]`. No backticks, spreads, variables or calls inside meta.
- `const A = typeof args === 'string' ? { <primary>: args.trim() } : (args || {})`, where `<primary>` is `workshop` for build-and-check, `question` for recon and `target` for second-opinion.
- `stage(label, fn)`: calls `fn()` in try/catch; a `null` or `undefined` result becomes `{ halt: '<label> returned nothing' }`; a thrown error becomes `{ halt: '<label> failed: <message>' }`. `halted(x)` is true when `x` is an object with a `halt` field.
- Every `agent()` call passes `label`, `phase`, `model`, `effort` and `schema`, plus `isolation: 'worktree'` and `agentType` where 6.4 to 6.6 say. `agentType` is left out when `A.agentTypes === false`; then the prompt's task starts with "First read <plugin root>/agents/<name>.md and follow it." (the plan's fallback for `agentType`).
- `parallel()` is called with an array of functions, each returning a promise (`parallel([() => ..., () => ...])`). `pipeline` is not used.
- A required argument that is missing returns `{ status: 'halted', halt: 'no <name> given: ...usage...' }` before any agent call.
- Plugin root: `R = A.pluginRoot || (the scope agent's returned plugin_root) || '<plugin root>'`. Prompts that point at plugin files (`R + '/rubric.md'`, `R + '/skills/launch/report-template.md'`) add, when `R` is `'<plugin root>'`: "find it as flightdeck/<path> in the repository, or under ~/.claude/plugins in the folder whose .claude-plugin/plugin.json names flight".
- No `Date.now`, `Math.random`, `new Date(`, `export default`, `import`, `require`. The date comes from `A.today` (when absent, prompts say "today's date (run date +%F)").
- The body ends with a top-level `return` of the result object.

### 6.4 `build-and-check.js`

- meta: `name: 'build-and-check'`, `description: 'Build and check one workshop task: a builder in its own worktree, script checks, review, adversary and imposter, one fix round, then a draft pull request'`, phases `Scope`, `Brief`, `Build`, `Check`, `Verify`, `Triage`, `Fix`, `Deliver`.
- Arguments: `workshop` (required; lowercase letters, digits and hyphens), `attempt` (number, default 1), `base` (default `'main'`), `dryRun` (default false), `today`, `pluginRoot`, `card` (the launch card text shown to the owner, optional), `task` (the owner's extra words, optional), `agentTypes` (default true). `BRANCH = <workshop>-a<attempt>`; `ATT = .flightdeck/<workshop>/attempts/a<attempt>`.
- Stages, with label, model, effort and options (the test pins this table):
  1. `scope`: haiku, low, RANK_TASK, not isolated, phase Scope. Task: from the repository root run `node <R>/lib/workshops.mjs scope <workshop> --json` (when `R` is unknown, try `flightdeck/lib/workshops.mjs` in the repository, then a `lib/workshops.mjs` under `~/.claude/plugins` whose plugin is named flight) and return its `block`, `checks`, `questions` and `warnings` exactly as printed, unedited, plus `plugin_root` (the folder used) and `notes`. Schema `{block, checks, questions, warnings, plugin_root, notes}`. If the returned `block` is empty, the script returns halted with `scope: workshop <name> has no folder (captured, not active): activate it first`.
  2. `brief`: opus, high, RANK_TASK, not isolated, phase Brief. Task: read the workshop's card `.flightdeck/<ws>/workshop.md`, its `constraints.md`, `context.md`, `verify.md`, the answered questions in `questions.md` and `decisions.md`; the launch card `A.card` and the owner's words `A.task` (quoted in the prompt); on attempt k > 1 the previous attempt's `findings.md` and `report.md` from branch `<ws>-a<k-1>` with `git show`. Return `brief_md` (markdown: the launch card first, then the task, the files the builder may write, the checks quoted verbatim from `verify.md` (the scope stage's `checks`), the done line as yes-is-pass questions, the five-minute try steps for the owner, and anything decided with a reason), `files` (paths the builder may write, never the workshop's `constraints.md`, `context.md`, `verify.md` or `.flightdeck/workshops.md`), `try_steps`, `done`, `title` (short) and `notes`. Schema `{title, brief_md, files, try_steps, done, notes}`.
  3. `build`: sonnet, high, `isolation: 'worktree'`, `agentType: 'flight:builder'`, SEAT.builder, phase Build. Task: first command exactly `git switch -c <BRANCH> <base>`; write `<ATT>/brief.md` with the brief text verbatim and commit it first; then make the change, writing only the brief's `files` and the attempt folder; run the workshop's checks; commit by file name (never `git add -A`); do not push; last command `git switch --detach` so the branch is free for the next stage. Return `{branch, commit, files, status, notes, captures}` with status one of `complete`, `blocked`, `contradiction-found`, `over-budget`. Any status other than `complete` makes the script return halted with `build: <status>: <notes>` (captures kept in the result).
  4. `check`: haiku, low, `isolation: 'worktree'`, RANK_TASK, phase Check. Task: `git switch --detach <BRANCH>`; write `git diff <base>...<BRANCH>` to `<ATT>/diff.patch` and `git diff --name-only <base>...<BRANCH>` to `<ATT>/changed.txt` in this worktree (never staged or committed); then run, in this order, the global checks (6.1) and then the workshop's checks from the scope stage, each listed one per line in the task; record exit code and the last 20 lines; skip a global check whose file is absent. Return `{worktree, diff_path, changed_path, results: [{command, exit, tail, skipped}], notes}` with absolute paths (`pwd`).
  5. Verify, in parallel, no shared notes, phase Verify:
     - `review`: sonnet, high, `agentType: 'flight:reviewer'`, SEAT.reviewer, not isolated. Task lists: the brief (`git show <BRANCH>:<ATT>/brief.md`), the diff file and changed list from the check stage, the rubric `<R>/rubric.md`, and "The workshop's questions:" followed by each scope `questions` line. Findings only on correctness or the brief.
     - `adversary`: opus, high, `agentType: 'flight:adversary'`, SEAT.adversary, not isolated. Task holds `=== The Work ===` (the diff file path, the changed-file list path, and the check stage's worktree path where the branch is checked out, all readable with Read) and `=== The Criteria ===` (the brief's done list, the rubric path, the workshop's questions one per line, the workshop's `constraints.md` path, `.flightdeck/VISION.md` and `.flightdeck/build.txt` where present). Cold mode; start at once.
     - `imposter`: sonnet, high, `isolation: 'worktree'`, `agentType: 'flight:imposter'`, SEAT.imposter. Task: `git switch --detach <BRANCH>`; adopt `.flightdeck/persona.md` (if present) and the `persona:` lines of the workshop's `constraints.md`; follow the brief's try steps literally, timing each; never run `claude plugin` commands that add, install, uninstall or remove anything, never start a nested `claude` session, never push; a step it cannot run is marked [stated]. Lists the workshop's questions too.
     - Each returns `{findings: [{severity, where, finding, evidence, suggested_fix}], verdict, timings}`. A verifier that returns null or throws is recorded as `{verifier, halt}` ("did not run") and does not halt the run.
  6. `triage`: opus, high, RANK_TRIAGE, phase Triage. Input in the task: every verifier result and every failed (non-skipped, non-zero) check result, which counts as a high finding. Return `{decisions: [{verifier, severity, finding, decision, reason}], fixes, questions, captures, proposals, high_accepted}`; `decision` is `accept`, `reject` or `question`; `questions` are blocks in the `questions.md` format (`## q<n>: ...`, `why:`, `options:`, `recommended:`, `asked: <today> by triage <ws>-a<k>`, `answer:`); `captures` are lines `- <name>: <the ask> (<today>)`; `proposals` are `context: <line>` or `verify: <line>` suggestions for the workshop's own files (an attempt never edits them).
  7. `fix` (only when `fixes` is not empty): sonnet, high, `isolation: 'worktree'`, `agentType: 'flight:builder'`, SEAT.builder, phase Fix. Task: `git switch <BRANCH>`; apply exactly the listed fixes; rerun the checks that failed; commit by file name; do not push; last command `git switch --detach`. One round only. Return `{commit, checks_green, notes}`.
  8. `recheck` (only when `fix` ran): haiku, low, `isolation: 'worktree'`, RANK_TASK, phase Fix. Task: `git switch --detach <BRANCH>` and rerun the same command list as the check stage. Return `{results: [{command, exit, tail, skipped}]}`.
  9. `report`: sonnet, medium, `isolation: 'worktree'`, RANK_TASK, phase Deliver. Task: `git switch <BRANCH>`; write `<ATT>/findings.md`, `<ATT>/report.md` and `<ATT>/log.md` in the formats of `<R>/skills/launch/report-template.md` (`report.md` is the pull request's body file, the input to `gh pr create`, and these three are the attempt's required record: writing them is this task); the task carries the brief, all stage results, the imposter's timings, triage's decisions, questions, captures and proposals, and a stage table (label, seat, rank Worker, model, effort) built by the script from its own calls. Commit the files by name. When `dryRun` is false: `git push -u origin <BRANCH>`, then `gh pr create --draft --base <base> --head <BRANCH> --title "<ws> a<k>: <title>" --body-file <ATT>/report.md`; if `gh` is missing or fails, write `<ATT>/pr.md` instead, commit it and say so. When `dryRun` is true: write `<ATT>/pr.md` (the title, then the body) and commit it; the task text then contains neither `git push` nor `gh pr create`. Last command `git switch --detach`. Return `{title, report_md, log_md, findings_md, pr_md, url, pushed, draft_reasons}` (the full texts, so the Captain can write any file the agent did not).
- Result: `{status: 'delivered', workshop, attempt, branch, base, dryRun, url, draft: true, title, brief_md, report_md, log_md, findings_md, pr_md, questions, captures, proposals, checks, verifiers}`; or on a halt `{status: 'halted', halt, stage, workshop, attempt, branch, captures}` returned straight away, with no later agent called. The pull request is always a draft; the owner merges.

### 6.5 `recon.js`

- meta: `name: 'recon'`, `description: 'Recon: three scouts read one question from separate angles, one summary, one claim check; writes no files'`, phases `Scope`, `Read`, `Summarise`, `Check claims`.
- Arguments: `question` (required), `workshop` (optional), `angles` (optional array of three strings; default `['what the documents say', 'what the code does', 'what earlier branches and history did']`), `lookIn` (optional paths), `today`, `pluginRoot`, `agentTypes`.
- Stages: `scope` (as 6.4, only when `workshop` is given; empty block halts the same way); `scout-1`, `scout-2`, `scout-3` in parallel: haiku, low, `agentType: 'flight:scout'`, SEAT.scout, phase Read, each told only its own angle, return `{answer, pointers: [{claim, where, confidence}], not_found}` (all three null halts with `scouts returned nothing`; one or two null are noted); `summary`: sonnet, medium, RANK_TASK, phase Summarise, writes one short summary from the three returns keeping every pointer and reading no sources itself, returns `{summary, claims: [{claim, where}], not_found}`; `claims`: sonnet, high, `agentType: 'flight:reviewer'`, SEAT.reviewer, phase Check claims, task says "use Read, Grep and Glob only, never Bash; a pointer you cannot open is marked could not check", returns `{marks: [{claim, where, mark}]}` with mark `confirmed`, `wrong`, `unsupported` or `could not check`.
- Result: `{status: 'done', question, workshop, summary, marks, not_found, report_text}`; `report_text` is built by the script: the summary, then one line per claim with its mark and pointer, then what was not found.

### 6.6 `second-opinion.js`

- meta: `name: 'second-opinion'`, `description: 'Second opinion: review, adversary and imposter read one file, diff or branch with no shared notes, then one short summary'`, phases `Scope`, `Prepare`, `Read`, `Summary`.
- Arguments: `target` (required: a file path, a diff file path or a branch name), `base` (for a branch, default `'main'`), `workshop` (optional), `criteria` (optional text), `today`, `pluginRoot`, `agentTypes`.
