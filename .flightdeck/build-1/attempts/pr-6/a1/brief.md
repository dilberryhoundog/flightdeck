## 1. Purpose

PR 6 gives FlightDeck a laboratory: a place to test and improve FlightDeck itself that never ships as plugin content (with one forced exception, the eval cases, see decision D6-1). It holds: a warnings-only lint; two drills that cost no tokens (the sweep, which breaks one part at a time in a temporary copy and proves a check notices, and remove-part, which deletes each later pull request's files and proves everything else stays green); an interview drill that pits PR 3's workshop interviewer against an imposter who holds one fact back, scored mechanically; a team drill and a teammate-type check that the owner runs by hand; three eval cases for PR 1's parts (plain chat stays quiet, the adversary finds a planted defect, a workshop's own context reaches only the agents sent into that workshop); a climb workflow that improves one document at a time and says "within noise, do not merge" when that is the truth; the copied `export-html` toy project used as a fixture; the lab's rules file; and one test file for all of it.

After it lands the owner can type `node lab/drills/sweep.mjs` and `node lab/drills/remove-part.mjs` and see in seconds, for free, that FlightDeck's checks catch breakage and that every later part can be cut without breaking the rest ("if i like it but its too big, I cut it down"); run PR 1's eval cases for about two dollars; ask the pilot to run the interview drill (with PR 3 merged); and later run a climb.

## 6. Units

Every builder: first command `git fetch origin && git switch -c build-1-pr6-lab-a1-u<i> origin/build-1-pr1-basic-a1`; write only the unit's files; one paragraph per line in markdown, no hard wrapping, plain words; commit by file name with the two attribution lines; push `git push -u origin build-1-pr6-lab-a1-u<i>`; return the build-return schema.

Two traps every builder of a `.mjs`, `.js` or `.sh` file under `lab/` must avoid, because PR 1's hard-rule check scans those files:

- Ceiling trap: the check flags any text in a lab script matching `model` or `effort`, a colon, then a quoted value of `fable`, `best`, `xhigh` or `max` (regex `\b(model|effort)\s*:\s*(['"\`])([^'"\`\n]*)\2`). The plugin's own ceiling guard also refuses to launch a workflow script whose text holds `model` + colon + quote + any value containing `fable`, or `effort` + colon + quoted `xhigh` or `max`. So never write such a literal, not even in a comment or test; where a drill must plant a bad value, build it at run time from pieces, for example `['fa', 'ble'].join('')` and `['x', 'high'].join('')`, and build the key the same way (`'eff' + 'ort'`).
- Old-tool trap: the check flags any lab script containing the two-letter name of the old workspace tool, or its long hyphenated name, as a separate word (regex `(^|[\s'"\`(;&|/])(dw|dev-workspace)(?=[\s'"\`)]|$)`), comments included. Never write either name in a lab script; where the sweep plants one, build it from pieces (`['d', 'w'].join('')`).
