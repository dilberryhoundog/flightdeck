# Mining the cockpit branch for FlightDeck build-1

Summary: the cockpit branch holds one failed-by-its-own-admission system (the v1 cockpit, now at `flightdeck/.cockpit-archive/`, 792 files) wrapped around a small number of ideas and pieces that are worth taking. The usable parts are: the three-level role idea (commander, captain/pilot who dispatches and does no work, crew), the roster plus seat-dossier model for teams, the per-order workshop directory with an index and a "for the commander" list, the truth and advice rules (human writes truth, agents only add advice, truth locked during a build), the live and cold adversary practice with its measured mechanics, the measured agent-team facts, the adversarial mandate and rubric guide in `library/`, the testbench protocol (golden file plus mutations) and a handful of seat definitions. Almost everything else in the archive is a self-referential record system (prefixed ids, manifests, 28 schemas, a linter, approval states, a rename tool) that the owner called tedious and that Ds-010 itself says should not be rebuilt. The biggest trap for build-1 is that nearly every agent definition on the branch says `model: fable`, which is above the owner's Opus ceiling, so every file taken must have its model field changed. Nothing here is canon; every verdict below is mine, and every "ran" or "passed" is as reported in the branch's own files, which I did not re-execute.
