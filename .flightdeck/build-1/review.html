01

What you get

start here

FlightDeck becomes one Claude Code plugin called flight. A plugin is a bundle of add-ons you install in one go. It lives in one folder, flightdeck/, and you install it from this repository.

PR 1 gives you

  • A crew of 7 helper agents, led by a pilot agent. The pilot decides and sends out the others. It does not do the work itself.
  • A status card at the start of each pilot session, saying where things stand.
  • Safety guards that stop helper agents pushing to main, starting a model above your limit, or editing your own files.
  • Three team plans: Recon (look around and report), Build and check, and Decide.
  • Short rule files (CLAUDE.md) that Claude Code reads on its own where the work happens.
  • Extras: a one-command self-check (/flight:preflight), a one-page review checklist, and an optional "radio" way of talking (short replies, status first).

PRs 2 to 4 follow once you have tried PR 1: a page showing all work and the questions waiting on you, starting work by talking, and one command that turns "go" into a reviewed draft PR. PRs 5 to 8 are optional extras, off unless you include them.

Who is on the crew

Ranks show how much say each helper has. Opus, Sonnet and Haiku are Claude's models, from strongest and priciest to cheapest. Nothing runs above Opus at high effort (a setting for how hard a model thinks).

  • Commander: you. Set the truth, say go, merge.
  • Captain (pilot, Opus): leads your session and sends out the others. Does not build.
  • Major (adversary, Opus): attacks the work to find what is wrong.
  • Lieutenant (officer, Sonnet): runs one job alone in the background and reports back.
  • Sergeant (reviewer and human imposter, Sonnet): judge the work. The imposter plays you.
  • Corporal (worker, Sonnet): builds, inside its own list of files.
  • Private (scout, Haiku): reads and reports. Decides nothing.
  • Warrant Officer (librarian, Sonnet, PR 7 only): keeps the manuals.

Commander, pilot, officer and crew come from you. I picked the other rank names. You can ask for more theme or less in the answer box.

A normal chat stays normal. A plain claude chat gets no status card and no forced style. Your own edits and git commands are never checked. Two things do reach every chat: a helper agent started on a model above your limit is refused, and any helper agent a normal chat starts cannot push to main or write your own files. The plugin also adds a few hundred tokens of command descriptions to what Claude reads at the start of a session (a token is a small chunk of text, the unit usage is counted in).

What is in it

  • Seven agent definitions (a file that sets one helper's job, model and tools): pilot, officer, scout, worker, reviewer, adversary and imposter.
  • The status card. It appears only in pilot sessions.
  • Three guards. One stops helper agents pushing to main, force-pushing or deleting remote branches. One refuses a helper agent launch that names the top-tier models (fable or best), and a workflow (a script that runs many agents in steps) that names fable, best, xhigh or max.   • Three team plans, each with the opening message every crew member gets, plus a "ways to fly" page.
  • /flight:preflight: runs the checks on FlightDeck and reports on your machine.
  • Rule files, a one-page review checklist, a rules page with the rank table, a short profile of you for the human imposter, and the optional radio voice.
  • The workshop templates, build-1's own workshop files (with my choices listed so you can strike any), and the script that checks the hard rules.

What the guards do not catch

They are safety nets, not locks. The git guard does not see git run from inside a script or an alias. The "your files" guard covers Claude's edit and write tools, not a shell command that writes a file. The model guard does not check the model or effort a session is started with (--model, --effort, /effort), the ultracode setting, agent files that set a higher model, or the CLAUDE_CODE_SUBAGENT_MODEL setting. The machine-wide ceiling is Claude Code's own managed settings. /flight:preflight prints the lines to add, and says whether GitHub's own protection on main (the real hard stop) is on.

How we know it works

  • Claude Code's own plugin check passes, the hard-rule script passes, and the tests for the card and guards pass.
  • A live test in a throwaway copy of the repository, with a fake local remote so nothing real can be pushed: the pilot answers "Captain" and "Commander"; a helper told to write constraints.md is refused; a dry-run push to main is refused; plain chat gets no card; the radio voice shows (or moves into the pilot's own instructions).
  • The review, adversary and human imposter checks (section 4). You confirm the card is visible on screen the first time, because the imposter cannot see a terminal.

Choice A

What "working" means

The choice
A part works if: its quick script checks pass, the human imposter can follow its try steps, removing it breaks nothing else, and every problem found is fixed or listed with a reason. If the imposter could only read a step and not run it, the step counts as not tried and the PR arrives as a draft that says so.
Only these hard rules can fail a check:
  • Nothing is pushed to main.
  • No model or effort above Opus at high.
  • Nothing changes under dev/ or .claude/rules/.
  • No FlightDeck script calls dev-workspace.
  • No file changes outside the PR's own list.
The same script also checks a few structure rules (each agent's model matches the rank list, there is no plugin settings file, and launch, retry and promote cannot start on their own). Everything else is only ever a warning.
Why
You said "show me something that works great. and fits the goal." Scripts prove it works, the imposter checks it suits you, and the removal test proves you can "cut it down". Keeping my numbers out of pass/fail means you never fight a test suite.
