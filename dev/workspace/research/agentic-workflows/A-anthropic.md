# Agentic workflows from Anthropic's and Claude Code's own framing

## 1. What "agentic workflow" means from this angle

"Building Effective Agents" (anthropic.com/engineering, Dec 19 2024) defines workflows as "systems where LLMs and tools are orchestrated through predefined code paths," and agents as "systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks." Later Anthropic material treats "agentic workflow" as a spectrum between those two ends. The post's core advice is to "find the simplest solution possible" and add orchestration only when a single well-prompted call stops being enough.

Claude Code's glossary (code.claude.com/docs/en/glossary, current) defines the "agentic harness" as "the tools, context management, and execution environment that turn a language model into a capable coding agent," and the agentic loop as "gather context, take action, verify results, and repeat until done." Hooks, skills and MCP "plug into specific phases of this loop."

## 2. Recurring features

**Multi-agent orchestration, with named patterns.** One feature, two layers. Vocabulary: "Building Effective Agents" names prompt chaining, routing, parallelization, orchestrator-workers and evaluator-optimizer; "A harness for every task" (claude.dev, Jun 2 2026) names classify-and-act, fan-out-and-synthesize, adversarial verification, generate-and-filter, tournament and loop-until-done. Some overlap the 2024 set (fan-out with parallelization, loop-until-done with evaluator-optimizer); tournament, generate-and-filter and adversarial verification have no 2024 counterpart. Mechanisms: code.claude.com/docs/en/agents lists five ways to run work in parallel: subagents (workers that return a summary), agent view (research preview), agent teams (peer sessions, shared task list, experimental, off by default), dynamic workflows (a script holds the plan) and Projects (parallel cloud threads, public beta). The Agent SDK builds a custom orchestrator. Workers are always Claude sessions: "To involve a different tool, expose it to Claude as an MCP server." Strength: strong.

**Context engineering, including resets.** "Effective context engineering for AI agents" (Sep 29 2025) names compaction, structured note-taking and sub-agent architectures. Two harness posts add resets with a handoff artifact. "Effective harnesses for long-running agents" (Nov 26 2025) says "Compaction isn't sufficient" and uses an initializer agent plus a `claude-progress.txt` file. "Harness design for long-running application development" (Mar 24 2026) weighs the choice: "A reset provides a clean slate, at the cost of the handoff artifact having enough state for the next agent to pick up the work cleanly." Claude Code ships `/compact`, automatic compaction, CLAUDE.md plus auto memory, and subagents/skills. A claude.dev post (Jul 24 2026) reports removing "over 80% of Claude Code's system prompt" for newer models. Strength: strong.

**Planning before acting.** best-practices.md: "Explore first, then plan, then code." Plan mode (`Shift+Tab` or `--permission-mode plan`) separates exploration from execution, Claude can interview you with AskUserQuestion and write a spec, and the page notes plan mode "adds overhead." The Mar 24 2026 harness post opens with a planner agent that expands "a simple 1-4 sentence prompt" into a product spec. Strength: strong.

**Verification, in two forms.** In-run: separate the doer from the judge. The Mar 24 2026 harness post found agents evaluating their own work "tend to respond by confidently praising the work," and "Separating the agent doing the work from the agent judging it proves to be a strong lever." Claude Code ships `/goal` (a small model judges a stated condition after every turn; "a wrapper around a session-scoped prompt-based Stop hook"), Stop hooks, `/code-review`, and an adversarial-review step (a subagent reviews the diff in a fresh context). Offline: "Demystifying evals for AI agents" (Jan 9 2026) separates capability from regression evals, and notes a 100% eval "provides no signal for improvement." "Automating eval design and hillclimbing" (claude.dev, Sep 28 2026, the newest eval guidance) adds: pick cases a human judged hard, keep headroom below 100%, change one thing at a time against a held-out set. Offline evals measure the system, not a run, so they may belong with another angle. Strength: strong.

**Deterministic guardrails under probabilistic judgement.** "How we contain Claude across products" (May 25 2026): "design for containment at the environment layer first, then steer behavior at the model layer," because users approved "roughly 93% of permission prompts." Auto mode "catches roughly 83% of overeager behaviors," and the same post says "~17% of overeager actions get through." Claude Code's side: hooks (deterministic, at fixed lifecycle points), permission modes, the sandboxed Bash tool, auto mode. The post is self-critical, with four "Risk we missed" cases: project config running hooks before the trust dialog, a phish in a controlled internal red-team exercise (24 of 25 retries exfiltrated), exfiltration through an allowlisted domain, and EDR blindness under VM isolation. Strength: strong.

**Skills, plugins, MCP and mods: the extension surface.** Skills: "Lessons from building Claude Code" (claude.dev, Jun 3 2026) reports "hundreds" in use, in nine categories; they follow the open Agent Skills standard. Plugins bundle skills, hooks, subagents and MCP servers as "a single installable unit" (glossary), with a `plugin.json` manifest, version-ranged dependencies, marketplaces, org control through managed settings, and `claude plugin eval` (Week 37, Sep 7-11 2026) to test against a no-plugin baseline in CI. MCP connects external tools. "Seeing like an agent" (claude.dev, Apr 10 2026) is about tool design: shape tools to the model's abilities and revisit them as models improve. Mods (claude.dev, Oct 1 2026, Claude Code 2.1.287+): "Under the hood, mods are hooks, and they ship inside plugins." Strength: strong.

**Unattended operation: three separate features.** (a) Completion loops: `/goal`, `/loop` (re-run on an interval), Stop hooks. (b) Triggers: routines (research preview) run a saved prompt on Anthropic cloud on a schedule, an API POST, or GitHub PR and release events; also desktop scheduled tasks, `/loop` and cron tools, channels (an MCP server pushes events into a running session, research preview), and GitHub Actions. (c) Supervising many sessions: agent view (research preview), cross-session messaging, Projects (public beta, Pro and Max only, gradual rollout, waitlist). Strength: moderate; most are preview or beta.

**Hosted and CI surfaces.** Managed Agents (beta, header `managed-agents-2026-04-01`) offers multi-agent orchestration: a coordinator delegates to agents in persistent "session threads" that share a sandbox but keep separate context. Claude Code GitHub Actions answers `@claude` mentions and turns issues into pull requests; Code Review runs multi-agent PR review; `/ultrareview` runs a cloud review (research preview since Apr 2026). Strength: moderate.

## 3. Guidance on use

Anthropic's consistent message is to start simpler than you think you need. The multi-agent research post (Jun 13 2025) says multi-agent systems "excel at valuable tasks that involve heavy parallelization, information that exceeds single context windows, and interfacing with numerous complex tools." Its lead-plus-subagents setup beat single-agent Opus 4 by 90.2% "on our internal research eval," but agents use "about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats." Domains with shared context or "many dependencies between agents are not a good fit... today. For instance, most coding tasks involve fewer truly parallelizable tasks than research."

Newer material narrows that. claude.com "Building multi-agent systems" (Jan 23 2026) names three cases (context protection, parallelization, specialization), puts cost at 3-10x tokens, and endorses a verification subagent for code. "Patterns and problems in emerging multiagent systems" (Aug 13 2026) reports 45 coordinating agents finding 266 vulnerabilities over 27M tokens against 21 for independent agents over 6.5M (Mythos Preview), but swarms building a game, where agents depend on each other, produced poor results: older models' PRs conflicted and were abandoned, newer models barely shared code.

agent-teams.md: "For sequential tasks, same-file edits, or work with many dependencies, a single session or subagents are more effective." workflows.md lists "a codebase-wide bug sweep" and "a 500-file migration" as uses and warns a run "can use meaningfully more tokens than working through the same task in conversation." Its table sorts mechanisms by who holds the plan (Claude or a script), not by cost. Working rule: independent, parallelizable coding work fits multi-agent; interdependent same-file work does not.

## 4. Hype or churn

Preview status is widespread: routines, agent view, channels and `/ultrareview` are research preview; Projects and Managed Agents are beta; agent teams and agent hooks are experimental (hooks.md: "For production workflows, prefer command hooks"). Mods shipped days before this research; they build on hooks and plugins, so the open question is API stability ("The API can change between releases"), not overlap. The `ultracode` keyword and workflow size guidelines are version-gated in workflows.md. I could not independently confirm the figures in "How we contain Claude" (93%, 83%) or the multiagent post (266); treat them as Anthropic's self-reported numbers.
