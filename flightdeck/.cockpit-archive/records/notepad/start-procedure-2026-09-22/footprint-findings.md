# Start procedure — footprint findings

Seat: trim-critic (T018, fit-and-footprint). Angle: what the session start procedure loads and what it costs. Tokens estimated at 4 bytes per token. Measurements are `wc -c` on the cockpit at 2026-09-22.

## Round 0 — baseline, own measurements before the tracer's first round

**P1 — The start procedure costs about 13,100 tokens before the pilot greets the commander, and 15,300 if step 3's advice check is taken literally.** Own. Launch system prompt: `team/officers/pilot/pilot.md` 5,783 B (~1,446 tok), `team/officers/pilot/identity.md` 1,804 B (~451), `team/officers/commander/commander.md` 2,703 B (~676) — the three are joined by `base/bin/pilot.sh:24,116-123`. Hook stdout ~350 B (~88). `CLAUDE.md` 9,632 B (~2,408). Step 1: `work/missions/MANIFEST-missions.json` 1,961 B (~490) + `work/missions/M001-cockpit-setup.md` 10,450 B (~2,613). Step 2: `records/logs/MANIFEST-logs.json` 4,626 B (~1,157) + latest log `records/logs/2026-09-21_71b94de4.md` 9,263 B (~2,316) + this session's log 813 B (~203). Step 3: `commander/desk/in/requests/MANIFEST-requests.json` 4,744 B (~1,186), plus `CA004.md` 8,928 B (~2,232) if the unacted advice is opened. Step 4: `work/procedures/triggers.md` 878 B (~220). Total 52,203 B / ~13,054 tok, or 61,131 B / ~15,286 tok with CA004.

**P2 — Seven lines of `CLAUDE.md` are pointers to a file already in the pilot's system prompt: 566 B (~140 tok) that change nothing.** Own. `CLAUDE.md:27,32,34` (rules 5, 10, 12) and `CLAUDE.md:63-66` (crew protocol 4-7) each read "The pilot's; in `team/officers/pilot/pilot.md`". For the pilot the target is already loaded; for crew, `CLAUDE.md:17` already says nothing in `team/officers/pilot/` is addressed to them, so the pointer is a dead end. Replacement, 7 lines to 1: "5, 10, 12 and crew protocol 4-7 are the pilot's, in `team/officers/pilot/pilot.md`." Saves ~470 B (~118 tok/session) and removes two numbered lists' worth of false content.

**P3 — Step 1 reads a 1,961 B manifest for a fact the hook printed 30 lines earlier.** Own. `base/bin/session-start.sh:28` prints `current_mission=M001`; `pilot.md:50` then reads `MANIFEST-missions.json`, whose only other start-relevant payload is the 743 B `progress` string. Cheaper: have the hook print `current_mission_path` and the current mission's `progress`, and let step 1 open the mission file directly. Net saving ~300 tok/session, and it removes a read whose cost grows with every mission added to the manifest.

**P4 — `MANIFEST-logs.json` grows 514 B per session and the pilot reads all of it to write one row.** Own. 9 rows, 4,626 B, ~1,157 tok today; ~26 KB / ~6,400 tok at session 50. The hook already prints `latest_log` (`session-start.sh:31`) and `indexed=`, so the read exists only to append. `base/bin/cockpit_store.py` already exists as the write path. Cheapest fix: the row is appended by a command, not by Read-then-Edit, and the manifest never enters context. Saves ~1,157 tok/session now, unbounded later.

**P5 — Step 3 reads 14 request rows to find the 1 the hook already named.** Own. `MANIFEST-requests.json` is 4,744 B / ~1,186 tok; status counts are 6 amended, 4 executed, 2 withdrawn, 1 superseded, 1 awaiting. `session-start.sh:33` prints `requests_awaiting=1 Rq012`. Nothing in the other 13 rows reaches the pilot's next action. Cheapest fix: delete the manifest read from step 3 and act on the hook line, opening the unit file only when the count is non-zero. Saves ~1,186 tok/session, rising as requests accumulate.

**P6 — Step 3's advice check asks a question no file can answer, so the honest reading costs 2,232 tok/session.** Own. `pilot.md:52` says check `commander/desk/out/advice/` "for advice not yet acted on". `MANIFEST-commander-advice.json` rows carry `id`, `answers`, `date`, `path` — there is no acted-on field. A pilot obeying the step must open the newest file, `CA004.md`, 8,928 B (~2,232 tok), every session to find out. Cheapest fix: add a `status` field to the advice rows so the manifest answers the question in one line, or state the check in terms of the decisions manifest, which already records what an advice file produced.

**P7 — 31 of M001's 40 objectives are ticked, and their 4,352 B (~1,088 tok) are re-read every session.** Own. `work/missions/M001-cockpit-setup.md` is 10,450 B; `grep -c '^- \[x\]'` returns 31 against 9 open. Finished objectives change nothing in the pilot's next action. Cheapest fix: fold the ticked items into one line per phase under a `## Done` heading and keep the 9 open ones in full. Saves ~1,000 tok/session and stops the file growing monotonically for the life of the mission.

**P8 — The mission `progress` field is a session log living inside a manifest, and it duplicates the mission file's open objectives.** Own. M001's `progress` is 743 B, M002's 444 B, both single prose paragraphs; M001's lists WS027, WS028, Rq012, CA004, P006 — items also carried as unticked objectives in the mission file read seconds later in the same step. Unbounded: every session appends. Cheapest fix: cap `progress` at one sentence and a date, since the mission file carries the detail, and the manifest is what a reader scans.

**P9 — The launch system prompt states the same three facts twice or three times.** Own. "Every session on this machine is the commander's. Address them politely and with authority" — `CLAUDE.md:19` and `commander.md:34`, near-verbatim. "Decide, then propose. Do not hand the commander a question you can rule on yourself" — `pilot.md:18` and `identity.md:24`. "Cheap crew do the reading" — `pilot.md:16` and `identity.md:27`. Roughly 600 B of the 10,290 B launch prompt. Bearing on Or064 (fold `identity.md` and `commander.md` into the body): a fold that concatenates saves nothing; the saving is in deleting the second statement of each fact, and the fold should be judged on the byte count after, not on the file count.

**P10 — The hook is the cheapest instrument in the procedure and is under-used.** Own. Six printed lines, ~350 B (~88 tok), and every one replaces a file read of 878 B to 4,744 B. Standing test for every tracer finding and every proposed fix: if the start procedure opens a file to extract a single scalar, that scalar belongs in the hook output instead. P3, P4, P5 are all instances.

**P11 — Watch item, not yet a finding: the latest-log read is the one large read I cannot call waste.** Own. `records/logs/2026-09-21_71b94de4.md` is 9,263 B (~2,316 tok) and log sizes range 4,671 to 31,915 B (`2026-09-18_dcb75456.md`). It is the only handover between sessions, so it earns its place; but nothing caps it, and one 31,915 B log is ~7,980 tok of start cost on its own. If the tracer proposes anything that adds to the log, that proposal must come with a cap.

## Round 1 — against trace.md T1 to T11 (T10 skipped, fixed)

**P12 — T1's fix costs 1,344 tok a session and lands on the wrong object.** Attacks T1. "Open every unit with status `in_progress`" adds `work/missions/M002-self-sustaining-cockpit.md`, 5,375 B (~1,344 tok), which is 0 ticked and 9 open objectives. Cheaper: make `current` a list, have the hook print the paths (P3), and open the mission the shift's work is under. If both must open, land P7 first — trimming M001's 31 ticked objectives (~1,088 tok) pays for four fifths of T1's addition.

**P13 — T3's second option buys one boolean for 1,018 tok a session.** Attacks T3. Option A, an `acted` field on the advice rows, costs about 20 B per row inside a 1,335 B manifest and answers where the pilot is already looking. Take option A. This is P10's test: never open a file to derive a scalar a field could carry.

**P14 — T6's fix, worded as it is, will pull a 2,832 B manifest into step 4.** Attacks T6. `work/procedures/MANIFEST-procedures.json` is 2,832 B (~708 tok) against `triggers.md` at 878 B (~220 tok), and its ids, paths and statuses answer nothing the start asks; the start asks only whether a condition has arrived. **P15 — T8's fix points at a 2,459 B README to state a shape the pilot already has open.** Attacks T8. `records/logs/README.md` is 2,459 B (~615 tok); step 2 reads the latest log in the same breath, and that log is the shape. **P16 — T8's second half adds a sentence to the most-read file in the cockpit to describe an absence.** Attacks T8. `CLAUDE.md` is loaded every session; `base/verify/lint.yaml:1-4` already states the session-log exemption and is never in the start read set. **P17 — The root under T4 and T5 is that `CLAUDE.md` rule 2 is a 1,744 B docspec loaded every session for a task performed occasionally.** Own, bearing on T4 and T5. `CLAUDE.md:24` is one line of 1,744 B (~436 tok), the largest rule in the file; it is the manuals docspec, needed when writing a manual. **P18 — T11's fix puts two more files in the path of a step that should not enter the room.** Attacks T11. `CLAUDE.md:78` tells every arrival "Start there", so a new README in `in/requests/` and `out/advice/` becomes start-time load; the cockpit's 36 READMEs average 1,315 B and `in/dossiers/README.md` is 1,280 B, so two at that size is ~640 tok a session. **P19 — T2 is right and free, and its urgency is borrowed from a trip that should not happen.** Attacks T2. `commander/desk/README.md` is 911 B and is not in the start read set today; repointing four lines costs nothing. **P20 — Round 1 as written grows the start by about 3,700 tok a session and saves nothing.** Own, over T1 to T11. ## Round 2 — against trace.md T12 to T18

**P21 — T14's fix is right and nearly free, on one condition: it must replace the read, not precede it.** Attacks T14. Printing the `current` id plus every `in_progress` id costs about 20 B of hook output. But ids alone still force `MANIFEST-missions.json` open to resolve id to path, which is the 490 tok P3 is trying to remove. Print the paths: `current_mission=M001 path=work/missions/M001-cockpit-setup.md`, one line per open unit. About 60 B (~15 tok) buys the removal of a 1,961 B read.

**P22 — T15's sort is free; the README line it comes with is not the rule.** Attacks T15. Sorting `others` by `date` at `session-start.sh:29-31` is one expression and zero context. Stating an ordering rule in `records/logs/README.md` documents a constraint that the sort would enforce, in a file nothing at start reads — it adds bytes to the cockpit and buys nothing the sort has not already bought. Take the sort, drop the README line. The absent line on a first-ever session costs nothing: absence is the cheapest output there is.

**P23 — T15's evidence shows P4 has a zero-cost home: the hook has already parsed the logs manifest.** Own, from T15. `session-start.sh:21` loads `MANIFEST-logs.json` into memory to compute `log_name` and `latest_log`, then prints two scalars and discards it. Appending the session's row there costs no context at all and removes the pilot's 4,626 B (~1,157 tok) read of the same file, which exists only so a row can be written. The hook already knows `session_id`, `session`, `date` and `path`; only `summary` is the pilot's, and step 2 already writes it as a placeholder.

**P24 — T16 found the symptom; the structure is that request rows never leave.** Attacks T16. Advancing six rows from `amended` to `executed` is right and changes no byte count: the rows stay. 13 of 14 rows are in a terminal state; a manifest carrying only the awaiting row is 296 B against the current 4,743 B. Move terminal rows to a done or frozen manifest, as `records/logs/FROZEN-crew-dispatches.json` already does for dispatches, and step 3's read falls by ~1,112 tok a session and stops growing at 339 B per request forever after.

**P25 — T17's third site is the finding: delete the clause from `CLAUDE.md`, do not correct it in three places.** Attacks T17. The same fact is stated at `pilot.md:53`, `CLAUDE.md:76` and `work/procedures/README.md:5`; two of those three load every session, and `work/procedures/README.md` is 3,018 B that nothing at start reads. A room's contents are the room README's job. Cut `CLAUDE.md:76` to the bare `procedures/` — the correction then has two sites instead of three, and one fewer place to go stale.

**P26 — T12 and T13 confirm the launch prompt has no hidden second copy; 10,290 B is all of it.** Own, on T12 and T13. `pilot.sh:24` appends `identity.md` and `commander.md` and nothing else, and `job.md` (1,038 B) and `team/officers/pilot/README.md` (643 B) are loaded by no path. That is the correct state and no fix should change it: the duplication that does cost is the restated content inside the three files that are loaded (P9), not the two that are not.

**P27 — Round 2 costs about 15 tok a session and can be made to save about 2,270.** Own, over T12 to T18. Nothing in this round adds a file read. T14 adds ~15 tok of hook output and removes 490; T15 is free; T16 taken structurally (P24) removes ~1,112; P23, which T15's evidence makes possible, removes ~1,157; T17 taken as P25 removes a few dozen bytes from a file read every session. This is the shape a round should have. Compare round 1 at +3,700.

## Round 3 — against trace.md T19 to T24, and the closing total

**P29 — T20's real cost is the clause before the one it corrects: Paperwork orders a schema read before every document.** Attacks T20. The 17 files under `base/verify/schema/` total 39,997 B, averaging 2,353 B (~588 tok) each; `dossier.json` is 1,847 B, `manual.json` 2,469 B, `request.json` 2,424 B. **P30 — T21's clause should be the same clause as P16's, not a second one.** Attacks T21. **P31 — T22 is free and should be taken, and it exposes 120 B of launch prompt that is addressed to no one.** Attacks T22, own addendum. Restamping costs nothing. Separately: the `stamp`, `type` and `unit` frontmatter of `identity.md` and `commander.md` is about 120 B of the 10,290 B launch prompt and the pilot never acts on it — it is search metadata for files that are delivered, not searched. **P32 — T23 and T24 cost nothing either way, and T24 is worth stating as a rule.** Own, on T23 and T24. `officer.json`'s stale room name is a zero-cost fix in a file the start never reads. It is correctly absent from the session start and must stay absent: a currency duty is not a reason to load a manifest at launch.

**P33 — Closing total: every cheapest fix taken, the start procedure runs at about 35,800 B / ~8,950 tok, down from 52,203 B / ~13,054, a 31 per cent cut.** Own. Launch prompt 9,690 B after P9's deduplication (~2,423 tok). Hook 410 B after P21's paths (~103). `CLAUDE.md` 7,528 B after P2 (−470), P17 (−1,624), P25 (−40) and P16/P30 (+30), at ~1,882 tok. Against the literal reading of step 3 today, 15,286 tok, the fixed procedure is 41 per cent smaller.
