## 1. What a created roster includes to perform on each axis

Each axis is a dial the team-builder sets when it writes a roster, by adding a seat, writing a dispatch instruction, or requiring a behaviour inside the run. This flight's events appear below only as illustrations of a mechanism, never as a score.

- **Speed** — "how quickly can the team run finish and its token efficiency but keep performance?" *Behaviour:* the paper-holder drafts from the start and revises on incoming evidence rather than waiting for it. *Dispatch instruction:* name the rounds a pass absorbs before the write begins, and freeze by pass number. *Seat:* none needed — Speed is bought by shape, not by staffing. Model choice is a Speed lever, since a stronger seat can cost fewer rounds than a cheaper one plus a repair round.
- **Coverage** — "How wide does the team cast a net for source material?" *Seats:* parallel readers on disjoint source classes, which is what makes the net wide rather than deep in one place. *Dispatch instruction:* name the source classes each seat owns so two seats do not fetch the same page, and require a raw fetch behind any negative claim.
- **Quality** — "the teams' result has project fit and small footprint?" *Seat, his example made concrete, and the seat already exists:* `trim-critic`'s purpose line is "Attack for bulk: what can be trimmed or replaced without losing function, with what is lost stated per cut, in tokens per session" — which is his mid-run question word for word, except that it has been flown three times and always at the end. By Or081 the body is universal and the posture is a dispatch property, so **the Quality inclusion is `trim-critic` dispatched live rather than cold**: the same seat, asked the same question, while the change can still be made smaller. It is cheap because it needs no new context, only the diff so far. *Behaviour:* every proposed addition carries its size — files touched, lines, new keys — so the question has something to bite on.
- **Alignment** — "team aligns with external and internal best practices?(anthropic, manuals)" *Seat:* a verifier that checks any claim about the harness or the practice against a cited source before the team builds on it. *Dispatch instruction:* no harness claim reaches a builder as settled without a source, and a stub manual is never cited as authority.
- **Security** — "does the team cross boundaries and look where it shouldn't?" *Dispatch instruction:* an enumerated read scope and one write path per seat, plus a standing instruction to disclose rather than suppress an out-of-scope result that arrives by accident. *Behaviour:* the seat reports the exposure and rests no finding on it.
- **Adversarial** — "can the team justify its output against criticism?" *Seats:* attackers in two postures, one live through the run and one cold at the end knowing nothing of what happened, which Or081 makes one body with different dispatch instructions and timing. *Behaviour:* the product is frozen by pass number before it is attacked, and every finding is answered finding by finding.

**What each type pays, and the inclusion that pays it back.** Stated as mechanisms a created roster would carry, not as scores for any dispatch.

- **Autonomous** pays Adversarial, since nothing rules between rounds. *Inclusion:* a cold adversary dispatched at the end — by Or081 the same body, differing only in dispatch instructions and timing, so the posture costs no new seat.
- **Pilot leader** pays Alignment, because the pilot's own harness claims sit on the critical path. *Inclusion:* a verifier seat, and a dispatch instruction that no harness claim reaches a builder as settled without a source.
- **Commander in the room** pays Speed, in rounds. *Inclusion:* the numbered freeze, **acknowledged by the writer**, since the freeze itself is derived from a pass number and an mtime but the acknowledgement is not.
- **Commander at the seat** trades a relay round for a record gap, since a ruling given at a seat never reaches `commander/orders/`. *Inclusion:* the filing step, the seat writing the ruling back verbatim, with the transcript as fallback.
- **A brief line every roster should carry**, and it is a Security inclusion rather than a Security score: "disclose what you saw outside your boundary, and rest no finding on it." Two seats did this unprompted when a grep returned out-of-scope content; a roster should not rely on that being instinctive.

**Tradeoffs when tuning.** Coverage and Speed pull apart, since every added source class is a seat and a round; Adversarial and Speed pull apart the same way, and the cold posture costs a whole extra pass by design because it must read a settled document. Quality's footprint dial pulls against Coverage, because a wider net returns more that could be written down. Security pulls against Coverage directly: a narrower read scope is a smaller net. The pair that does not conflict is Alignment and Adversarial, which share a seat cheaply, since a verifier that sources claims is most of what an attacker needs. His rule governs the sum: no arbitrary seat count, the test is in the performance.
