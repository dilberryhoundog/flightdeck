# XX-001 — One file per advice unit, or one file per piece of advice

Both sides are sentences inside the same record, CA-007, extracted from `cockpit.constitution` line 29, which sets the shape of commander advice.

## CA-007 (29.2)

"Advice is grouped into single conceptual units of infrastructure, with each file containing all the CA pertaining to that conceptual unit." [29]

## CA-007 (29.5)

"A single unit of infrastructure becomes a sub directory of CA, A unit manifiest is created which reads each relevant CA." [29]

## The contradiction

The first sentence says a unit is one file that contains every piece of advice on that unit, so the file is the unit. The second says a unit is a sub directory holding each piece of advice separately, with a unit manifest that reads them, so the directory is the unit and each CA is its own file. Both cannot describe the same thing: if each file already contains all the advice for its unit there is nothing for a unit manifest to read, and if a manifest reads each relevant CA then no single file holds them all. CA-007 contradicts itself. The cockpit has been built to the second sentence, at `records/commander/advice/identifiers/` with `CA-001.json` beside `MANIFEST-identifiers.json`, and the corpus migration is filing every unit that way, so a ruling for the first sentence would mean rebuilding what is already on disk.
