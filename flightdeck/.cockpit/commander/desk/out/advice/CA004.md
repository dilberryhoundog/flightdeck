#### Dossier

Two types:
direct invocation - Agent exists only as a "dossier", pilot builds from this template to satisfy a role when spawned. Unable to utilise agent frontmatter for hooks, model, tool restrictions.
Agent definiton - An agent file that gets its own system prompt and metadata. Dossier provides invocation guidance, but not role and restrictions.

Entry Point:  
Key to seat performance, this field builds the pilots dispatch message to each seat.
Contains a generalised role definition that applies to all dispatches (defined agents are just refenced).
Targeted role variations this seat can undertake. Dispatch stage variations, focus or criteria variations this crew can do.
Tasks to perform, Output to produce. Anything the seat needs to do or know during the run needs to be defined here.

Dossier core functions:
**entry_point** - The lead's dispatch generator. Replaces "how to dispatch" in the current format. 
**conduct**  - the list of duties the lead must perform to manage this agent while it is active in the team. replaces parts of "lead_duties" proposed field. 
**improvement** - list of improvements discovered during dispatches while in the seat. 
**test** - predefined testing methods that the seat can run to maintain / improve performance.

#### Procedures

No procedure residue in team files. Procedures are standalone. They join parts of the cockpit with actions the pilot can take into a repeatable chain. Integrating them into other cockpit fitout, only increases maintenance burden for little gain.

The current P002 procedure upon relection is not redundant, The questionaire requirement is probably best being a step before team dispatch. This procedure was an initial attempt, I do think it can be expanded expertly from our findings into a better version that fits team mechanics better.

### Dispatch stages

Enables isolation of agents. Seats dispatched in stages to enable better individual performance. (once introduced agent is no longer isolated.)

**live** - During the main run, where the bulk of the work is conducted.

**setup** - Before the main run, collects information, builds context to increase performance of the main run bulk work.

**end** - After the main run has settled,

**full** - All stages combined. present from setup to end.
