=== 3. WHAT EXISTS NOW ===
Every ID-based work and desk document, every manual and every crew and officer dossier opens with frontmatter between two --- lines. Common: type, unit, stamp. Chain: work (the mission), context (the link behind, a list of ids), generates (the link ahead, a list of ids). By type: request adds status; mission adds status, branch, assigned_by; spark adds heat, raised_by and an optional status; procedure adds status, trigger, approved; manual carries source or stub: true, and style, and no unit; crew dossier carries room, agent_type, model, status with the seat name as unit. Example, a request:
  type: "Request" / unit: "Rq013" / status: "amended" / stamp: ["2026-09-20", "Pilot: Ace", "b27e6c01"] / work: "M001" / context: ["Ds006"] / generates: ["De026", "De027"]
Bolded metadata blocks were removed where frontmatter replaced them; lines holding facts frontmatter cannot (a dossier's From line, amendment notes) were kept. The CLAUDE.md Paperwork section states the convention and how to search it.

--- THE PILOT'S RULINGS (not the commander's words; keep, change or strike) ---
- Lists are bracketed (["Rq004", "Rq005"]); the comma form in the first Ds001 example does not parse as YAML, so the linter names the line and shows the bracketed form.
- stamp is one key, a three-item list in fixed order: date, author, eight-character session id.
- context and generates are not mirror images: a dossier generates its requests (checked both ways); advice attaches to a dossier without being generated by it.
- context may be an empty list where there is no link behind (the first three requests, a seat that has never flown).
- An advice file gained a fifth, optional field, status (awaiting or answered), so the draft procedure P006 can create an empty advice file for the commander to answer without falsely stamping him as its author. This goes beyond the commander's four fields.
- Values for old documents were taken from their own text, manifest rows and the session logs, never invented.
