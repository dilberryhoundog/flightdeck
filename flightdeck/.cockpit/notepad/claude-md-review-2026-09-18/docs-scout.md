## Findings
F1. CLAUDE.md files are markdown files giving Claude persistent instructions for a project, personal workflow, or organization; Claude reads them at the start of every session, alongside Claude's separately-written "auto memory" of learnings and corrections. https://code.claude.com/docs/en/memory
F2. Use CLAUDE.md for coding standards, workflows, and project architecture; use auto memory for the user's preferences, corrections, and project context Claude can't derive from the code — the two systems are complementary and both load every session. https://code.claude.com/docs/en/memory
F3. Add to CLAUDE.md when Claude repeats a mistake, a code review catches something Claude should have known, you retype the same correction across sessions, or a new teammate would need the same context; a multi-step procedure or content relevant to only part of the codebase belongs in a skill or a path-scoped rule instead. https://code.claude.com/docs/en/memory
F4. Recommended size is under 200 lines per CLAUDE.md file; longer files consume more context and reduce instruction adherence, and files over 4 MiB are skipped entirely. https://code.claude.com/docs/en/memory
F5. Best-practice guidance frames every line as a cost/benefit test: "Would removing this line cause Claude to make mistakes? If not, cut it" — a bloated CLAUDE.md causes Claude to ignore real instructions. https://code.claude.com/docs/en/best-practices
F6. Include: bash commands Claude can't guess, code style rules that differ from defaults, testing instructions/preferred test runners, repo etiquette (branch naming, PR conventions), project-specific architectural decisions, environment quirks (required env vars), and common gotchas. Exclude: anything derivable by reading the code, standard language conventions, detailed API docs (link instead), frequently-changing information, long tutorials, file-by-file descriptions, and self-evident practices like "write clean code." https://code.claude.com/docs/en/best-practices
F7. `@path/to/import` syntax expands and loads a file into context at launch; both relative and absolute paths work, relative paths resolve relative to the file containing the import (not the working directory), and recursive imports go up to a maximum depth of four hops. https://code.claude.com/docs/en/memory
F8. Import parsing skips markdown code spans and fenced code blocks — wrapping a path in backticks keeps it literal instead of triggering an import; splitting content into imports helps organization but does not reduce context, since imported files still load at launch. https://code.claude.com/docs/en/memory
F9. An import in a project-level memory file that resolves outside the working directory (e.g., a home-directory path) is "external"; Claude Code shows a one-time approval dialog listing such files the first time they're encountered, and declining disables them permanently for that project. https://code.claude.com/docs/en/memory
F10. Memory hierarchy, broadest to most specific load order: managed/enterprise policy CLAUDE.md (IT-deployed, cannot be excluded) → user instructions at `~/.claude/CLAUDE.md` → project instructions at `./CLAUDE.md` or `./.claude/CLAUDE.md` (team-shared via source control) → local instructions at `./CLAUDE.local.md` (personal, gitignored). https://code.claude.com/docs/en/memory
F11. CLAUDE.md and CLAUDE.local.md in the working directory and every directory above it load at launch, concatenated (not overriding each other) from filesystem root down to the working directory, so instructions closer to the launch directory are read last; within a directory, CLAUDE.local.md is appended after CLAUDE.md. https://code.claude.com/docs/en/memory
F12. Subdirectory CLAUDE.md and CLAUDE.local.md files (below the working directory) are NOT loaded at launch — they load on demand only when Claude reads files in that subdirectory. https://code.claude.com/docs/en/memory
F13. `.claude/rules/` holds topic-scoped markdown files (one topic per file), discovered recursively including in subdirectories; rules without `paths:` frontmatter load at launch with the same priority as `.claude/CLAUDE.md`, while rules with `paths:` frontmatter (glob patterns) load only when Claude reads a matching file. User-level rules in `~/.claude/rules/` load before project rules. https://code.claude.com/docs/en/memory
F14. CLAUDE.md content is delivered as a user message after the system prompt, not as part of the system prompt itself — this is the documented reason strict compliance isn't guaranteed, especially for vague or conflicting instructions; for instructions wanted at the system-prompt level, use the `--append-system-prompt` CLI flag instead. https://code.claude.com/docs/en/memory
F15. Custom subagent definitions (`.claude/agents/*.md`) are a distinct mechanism from CLAUDE.md: each subagent runs in its own context window with its own restricted tool list and can specify its own model, and is invoked for isolated/delegated tasks rather than loaded as persistent session-wide instructions. https://code.claude.com/docs/en/best-practices
F16. Settings/hooks are enforced deterministically by the client regardless of what Claude decides, whereas CLAUDE.md and rules are advisory context Claude tries to follow but may not comply with strictly — use a PreToolUse hook, not CLAUDE.md, to hard-block an action. https://code.claude.com/docs/en/memory
F17. `/init` generates a starting CLAUDE.md by analyzing the codebase; if a CLAUDE.md already exists, `/init` suggests improvements rather than overwriting it, and `/doctor` can propose trims to a checked-in CLAUDE.md (cutting derivable content, keeping pitfalls/rationale/non-default conventions). https://code.claude.com/docs/en/memory
F18. `/memory` lists CLAUDE.md, CLAUDE.local.md, and other memory locations across scopes and opens any file in your editor; `/context` shows which memory files actually loaded into the current session. Asking Claude to "remember" something saves it to auto memory, not CLAUDE.md. https://code.claude.com/docs/en/memory
F19. Project-root CLAUDE.md survives `/compact` (re-read from disk and re-injected), but nested subdirectory CLAUDE.md files and path-scoped rules only reload when Claude next reads a matching file, so conversation-only instructions are lost on compaction. https://code.claude.com/docs/en/memory
F20. Block-level HTML comments in CLAUDE.md are stripped before injection into context, except comments inside code blocks; opening the file with the Read tool still shows all comments. https://code.claude.com/docs/en/memory
F21. Claude Code reads `CLAUDE.md`, not `AGENTS.md`; for repos using AGENTS.md the documented pattern is a CLAUDE.md that does `@AGENTS.md` import plus Claude-specific instructions below it. https://code.claude.com/docs/en/memory
