## What flightdeck is

`flightdeck/STRUCTURE.md` declares it an orchestration workflow tool for agentic software building, intended to eventually replace dev-workspace. `flightdeck/` is the scaffold installed into a project. Keep files name each directory's job and are permanent.

## What exists on main

- **Crew roles** in `flightdeck/flightcrew/crew/`: spec-builder, spec-judge, spec-attacker, test-builder, worker, isolated-worker, reviewer. `spec-interviewer.md` is empty by design. `crew.json` (778 lines) is the manifest of the whole run pattern with roles and gates.
- **Schemas** for spec, plan and tests-map, plus thin worker docspecs.
- **Templates**: liftoff config, spec, plan, tests-map, worker prompt, three markdown spec templates.
- **Checks**: spec readiness linter and five validators with a bulk walker.
- **Bin**: one worker prompt renderer. No CLI.
- **Manuals**: spec description and conventions, verification addendum, testing description and conventions, versioning, readiness rubric v2.2 with earlier versions under deprecated.
- **Testbench**: a rubric bench with results, a validator suite, and 80 git-ignored run logs from a characterization run (660 of 660 checks passed on 2026-09-16, six defects deliberately pinned).
- **`.claude/agents/`**: copies of six crew files plus adversary and a stub flight-assistant.
