## Subagents

- A role's `tools` field is a hard allowlist, so a role defined without Write has no way to produce a file. **Confirmed.** https://code.claude.com/docs/en/sub-agents (2026-09-18)
- A single unresolvable entry in `tools` fails the subagent at launch. **Contradicted.** The documented trigger is that *nothing* in the list resolves, and then launch *usually* fails naming the unresolved entries. https://code.claude.com/docs/en/sub-agents (2026-09-18)
- `isolation: worktree` is enforced, not advisory: Claude Code blocks a Bash or Monitor command when it cannot verify from the command text that any git the command runs stays inside the worktree, including when the command name is computed at runtime or the syntax cannot be parsed, and the check cannot be turned off. **Confirmed.** https://code.claude.com/docs/en/sub-agents, https://code.claude.com/docs/en/worktrees (2026-09-18)
- Hitting the turn limit loses the unit's work. **Contradicted.** At the `maxTurns` limit the output returns marked partial and Claude can resume it, partial marking from v2.1.246. https://code.claude.com/docs/en/sub-agents (2026-09-18)
- A subagent stopped deliberately, by `x` in `/tasks` or an SDK `stop_task`, does not auto-resume, and a message to it is refused as cancelled. **Confirmed.** https://code.claude.com/docs/en/sub-agents (2026-09-18)
- Prose in a role file can disown auto-loaded project instructions. **Contradicted.** Subagents load every level of the CLAUDE.md hierarchy by default, built-in Explore and Plan excepted; the only enforced suppression is `omitClaudeMd: true` from v2.1.271, it is ignored when the agent runs as the main session agent via `--agent` or the `agent` setting, and managed policy files still load, except where the agent definition itself comes from managed settings, in which case none load. https://code.claude.com/docs/en/sub-agents (2026-09-18)
- `initialPrompt` fires only for the main session agent, auto-submitted as the first user turn under `--agent` or the `agent` setting, and never on ordinary subagent dispatch. **Confirmed.** https://code.claude.com/docs/en/sub-agents (2026-09-18)
- Concurrency and depth are capped: `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` defaults to 20 and a further spawn fails with `Concurrent subagent limit reached`, from v2.1.217; `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` defaults to 3, three layers below the main conversation, from v2.1.219. **Confirmed.** https://code.claude.com/docs/en/sub-agents (2026-09-18)
- A fork started in session with `/subtask` and a resumed subagent occupy concurrency slots without being blocked by the limit, so the running count can exceed the cap. **Confirmed.** https://code.claude.com/docs/en/sub-agents (2026-09-18)
- `fable` is a valid model alias alongside `sonnet`, `opus` and `haiku`; Fable 5.1 requires v2.1.257, and neither Fable model is the account-type default on any plan or provider, so it is selected explicitly. **Confirmed.** https://code.claude.com/docs/en/sub-agents, https://code.claude.com/docs/en/model-config (2026-09-18)
- A role on `fable` sits below one on `opus`. **Contradicted.** The Fable models are documented as the most capable models in Claude Code, and the alias points at the hardest and longest-running tasks. https://code.claude.com/docs/en/model-config (2026-09-18)

## Worktrees

- Flightcrew's workflows README asserts that a subagent worktree branches from HEAD, unconditionally (`run/flightcrew-characterization-2:flightdeck/flightcrew/workflows/README.md` at `4fd81d8`). **Contradicted.** It branches from the repository's default branch unless `worktree.baseRef` is `head`, and falls back to the local HEAD only when no remote is configured or `origin/HEAD` is neither cached nor fetchable. https://code.claude.com/docs/en/worktrees (2026-09-18)
- Uncommitted work in the parent's tree is invisible to a worker running in a worktree. **Confirmed.** A worktree checks out a commit. https://code.claude.com/docs/en/worktrees (2026-09-18)
- Flightcrew's workflows README gives the base ref as the reason uncommitted files are invisible to a worker (`run/flightcrew-characterization-2:flightdeck/flightcrew/workflows/README.md` at `4fd81d8`). **Contradicted.** The base ref is not the cause; a worktree checks out a commit, so uncommitted files are invisible whatever the base ref is. https://code.claude.com/docs/en/worktrees (2026-09-18)
- `$CLAUDE_PROJECT_DIR` follows the agent into its worktree. **Contradicted.** It stays at the root where the session started; the worktree root is the `cwd` field of the hook's input JSON, which moves again when Claude runs `cd`. https://code.claude.com/docs/en/hooks, https://code.claude.com/docs/en/worktrees (2026-09-18)
- Starting a session in a worktree requires workspace trust, and non-interactive `-p` skips that check, so `claude -p --worktree` proceeds without it. **Confirmed.** https://code.claude.com/docs/en/worktrees (2026-09-18)

## Hooks, workflows, permissions, sandboxing

- The hook event names bound in settings are documented events, and exit 0 against exit 2 carries the documented meaning. **Confirmed.** https://code.claude.com/docs/en/hooks (2026-09-18)
- Every field of the hook stdin envelope arrives on every event. **Contradicted.** Four of the eight are conditional: `prompt_id` and `scratchpad_dir` are version-gated, `permission_mode` notes that not all events receive it, and `effort` is present only for events firing within a tool-use context, such as PreToolUse, PostToolUse, Stop and SubagentStop, when the model supports it. `session_id`, `transcript_path`, `cwd` and `hook_event_name` are the common fields. https://code.claude.com/docs/en/hooks (2026-09-18)
- A `PreToolUse` hook blocks only by printing a JSON decision. **Contradicted.** Exit 2 blocks on any blocking event whether or not JSON is printed, and beats a JSON `permissionDecision` of allow. https://code.claude.com/docs/en/hooks (2026-09-18)
- Eight consecutive blocks is a real ceiling: Claude Code overrides the hook and ends the turn. **Confirmed.** https://code.claude.com/docs/en/hooks (Stop input section), https://code.claude.com/docs/en/best-practices (2026-09-18)
- `WorktreeCreate` observes worktree creation. **Contradicted.** It replaces creation: any non-zero exit aborts it, and the hook prints the directory path Claude Code then uses as the session's working directory. https://code.claude.com/docs/en/hooks, https://code.claude.com/docs/en/worktrees (2026-09-18)
- A workflow runs as `/<name>` with its arguments passed as structured data, and the runtime makes `Date.now()`, `Math.random()` and a no-argument `new Date()` throw inside the script. **Confirmed.** https://code.claude.com/docs/en/workflows (2026-09-18)
- `Agent(<name>)` and `Workflow(<name>)` are both real permission forms, both documented. **Confirmed.** https://code.claude.com/docs/en/permissions, https://code.claude.com/docs/en/workflows (2026-09-18)
- `sandbox.filesystem.deny` and `permissions.deny` cover each other. **Contradicted.** They are independent: sandbox paths are enforced at OS level over every command and child process inside the sandbox, while Bash edits within sandbox boundaries run unprompted even in Manual mode, where the file edit tools would prompt. https://code.claude.com/docs/en/sandboxing (2026-09-18)
