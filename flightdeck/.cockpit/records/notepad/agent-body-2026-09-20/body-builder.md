## Things you would not guess

- `flightdeck/library/` is cited in `CLAUDE.md` rule 2 and does not exist on this branch. Pre-existing, in a rule the cut does not touch, so I left it. It is the one failure of "every path `CLAUDE.md` cites exists".

- **The agent definition's `effort` does not apply to a main session agent, and the launcher works around it with `--effort`.** The docs verifier could only report the precedence as undocumented; the pilot measured it in headless launches on CLI 2.1.278, reading the transcript's `effort` field. First measurement: `effort: medium` in the agent JSON with no `effortLevel` in the `--settings` file recorded `effort: high`, the commander's user-settings value. Second, after the commander removed `effortLevel` from his user settings: an agent JSON `effort` of `medium` and of `low` both still recorded `high`, so the definition's `effort` is not merely outranked, it does not apply at all; `--effort medium` beside the same agent recorded `medium`. So `pilot.sh` now reads `effort` out of the agents JSON it already built and passes `--effort` on every start and every resume, the same pattern as `--model`. `pilot.md` stays the single source for both, which is what the commander ordered; the model takes hold through the definition, the effort through the flag. `effortLevel` is out of `base/settings/pilot.settings.json` again. The measurement is now written out in one place, `base/bin/README.md`; `pilot.sh`'s header states the fact in one line and `base/settings/README.md` points at the bin README, so there is one copy to update when the harness changes. The finding still wants a line in the launch manual (`records/manuals/claude-code/settings-and-launch.md` still lists `effort` among the frontmatter fields with no word on this), which is the pilot's.
- The same measurement settled three of the four undocumented claims, all of them the way the build assumed: the agent's `model` applies (`claude-fable-5-1` with no `model` key in the settings file); the body reaches the model and `--append-system-prompt` lands on top of it; and under `-p`, `initialPrompt` is prepended to the `-p` prompt in a single first user turn. The claim still untested is whether an `@` import expands inside an agent body. `pilot.md` contains no `@` import, so it does not bite; the fourth pass removed the notepad test citation from `pilot.sh` and the claim now rests nowhere in the shipped files.
- "You preside over the room where crews thrash things out" keeps the word "room", which means a directory everywhere else in the cockpit (`CLAUDE.md`: "Five rooms, each answering one question"), and the body defines neither sense. The fit-critic raised this separately from duplication; the pilot has ruled the sentence stands as the commander wrote it. Recorded here so the collision is known rather than rediscovered: a future reader deciding the body needs a glossary line should start with this word.
- Still unmeasured: whether `initialPrompt` re-fires across `--resume`. That is the commander's next-shift test. The prompt is written to be safe fired twice and leans on the hook's `indexed=` line rather than on its own firing count, so a re-fire opens no second log either way. Effort on resume no longer needs measuring: the launcher passes `--effort` there too.
- On resume the launcher passes `--agents` and `--agent pilot` again, per the pilot's ruling of 2026-09-21. The transcript restores the agent's name, but the definition exists only in the launcher's JSON, and an agent the harness cannot resolve falls back to default tools with a warning.
- Crew do not inherit the pilot's body: a subagent or teammate spawned from a main session agent starts with its own definition's prompt only. That is the fact the cut depends on, and it is confirmed. Anything in `pilot.md` a crew member needs must be written into its brief.
- The frontmatter reader takes the first colon on a line, so a value may contain colons, and it does not unescape quotes, so no value may contain a quote of its own kind. Noted in the script's comment. Dropping the `"pilot"` default for `name` means a `pilot.md` without that key now dies on a `KeyError` at exit 1 and launches nothing, where before it would have launched under a guessed agent name. Tested. The traceback is ugly but it fails safe, and a message would have been the schema check the ruling removed.
- `APPEND_FILES` is a space-separated list in POSIX sh, so those paths must not contain spaces. Noted in the script.
- Nothing was committed or staged.
