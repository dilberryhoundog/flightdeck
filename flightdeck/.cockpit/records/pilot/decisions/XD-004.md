# XD-004 — Extracting the constitution and settling the record shapes

Answers CO-087. Runs first. Each unit opens `+`.

+ Every sentence of the constitution is classified as an order (pilot conduct), advice (project infrastructure), an idea (a forming exploration), a question, or a definition that is none of these, and filed at `records/commander/orders/`, `advice/<unit>/` or `ideas/`; definitions are not records and are left where they are.
+ The advice units are named from the constitution's own nouns (records, roles, locations, teams, crew, work, testing, package, identifiers) and become the unit list XD-003 uses.
+ One JSON schema per record type is written in `base/verify/schema/` in the existing style, selected by `type` as today, for CO, SO, CA, CR, CQ, CI, XD, XR, Ds, XX, XP and PP, plus the unit and global manifests; `cockpit-lint` is extended to select them and a seat runs it.
+ The glossary of prefixes is written as the table in `CLAUDE.md`, replacing the old ID table; the old prefixes are not listed.
+ Where two sentences of the constitution contradict each other, an XX is filed at `records/pilot/disputes/` with both sides shown.
+ Seats: `constitution-reader` (Opus) classifies and names units; `schema-builder` (Sonnet) writes the schemas and lint selection and runs the lint; `commanders-advocate` (Opus, standalone) checks every extracted record against the constitution's words; `fit-critic` (Opus) live from the first landing.
