# Sp004 — OS sandbox as a second write fence

## The spark

The guard hook is a parser and cannot see inside interpreter scripts. Claude Code's sandbox (`sandbox.filesystem` in settings, https://code.claude.com/docs/en/sandboxing) enforces write limits at the OS level for Bash and its child processes. It could back up mandate one where the guard is blind.

## What is unknown

- Whether `allowWrite` re-opens part of a `denyWrite` region. The docs show that pattern only for reads (red-team, S4).
- Denying writes to the repo root would deny `.git`, breaking commits, pushes and dev-workspace commands.
- How the sandbox interacts with `permissions.defaultMode: auto` and with teammates.
