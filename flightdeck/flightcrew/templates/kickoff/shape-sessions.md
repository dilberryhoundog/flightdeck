## Shape: sessions
The run is split across more than one Claude Code session against the same launch: one conducting session that owns the gates, and one further session per stream. A stream is a named set of unit ids drawn from the plan's waves; the conducting session assigns every stream and records the assignment with `fc launch note` before any stream session starts. A further session is opened by starting a new Claude Code session in the same repository with `FLIGHTCREW_LAUNCH=<launch>` set, running `fc launch status` first and reading this launch's kickoff.md and nothing else before it dispatches. The conduct sequence, the gates and every fc command are as the Conduct section above states them.
Dispatch: each session dispatches implementers for the units of its own stream only, and only from prompts rendered by `fc worker render` in that session. Before rendering a unit, a session confirms the unit is in its own stream by reading the assignment note with `fc launch status`; two sessions never hold the same unit. The conducting session divides the implementers_concurrent ceiling into a stated share per session when it assigns the streams, and each session holds to its own share.
Progress: the shared state is the launch folder — the stored returns, the events file at events.jsonl inside it, and the evidence page — together with the run branch and the unit branches in git. A session that needs to know what another has done reads `fc launch status` and the returns, never the other session's transcript. Only the conducting session stores returns with `fc return worker` and lands units with `fc worker merge` in wave order; stream sessions dispatch and hand their payloads to it.
Stopping: only the conducting session records gates and runs `fc launch end <accepted|accepted-with-reservations|abandoned|partial>`. A stream session runs `fc launch status` before each dispatch chunk, dispatches nothing while a gate is pending or an escalation is open, and stops dispatching and ends its turn once the launch status is no longer active. A stream session that meets a halt return, or that reaches one of the launch.json ceilings `fc budget` counts, runs `fc launch escalate <kind> --detail "…"` and ends its turn; the escalation is visible to every session through the launch folder.
