## Task: audit
The deliverable is findings and their evidence. Cut the units by question, one question per unit, and give each question unit the check id from the pinned tests map that reproduces what it claims: an audit finding without a reproduction is an opinion. A question whose reproduction check the pinned map does not carry is a spec gap, raised with `fc launch escalate spec-gap --detail "…"` before gate 1; no check is written during the run.
Wave 0 is the single `kind: contracts` unit and builds the harness the audit reads through — the script, the fixture or the query every later unit reuses — at `flightdeck/launch/<launch>/audit/harness/`, so that every finding is produced the same way; its own check is the harness's. Later units answer one question each and write their finding and its reproduction output to `flightdeck/launch/<launch>/audit/findings/<unit>/`, the path their plan entry grants and no fc command rewrites.
Read widely and write narrowly: a question unit's paths are its findings directory alone, and wave 0's are the harness directory. An allowed-path set arriving from the pinned tests map that is wider than the harness and the launch folder is an escalation, not something the plan narrows silently. A unit given no write path outside those returns a halt rather than applying a remedy it found; record the finding and dispatch no fix. Remedies belong to a later run against a spec written from these findings.
Risks worth naming: a question that cannot be answered from the repository, a finding that only reproduces on one machine, and a sweep that quietly becomes a fix.
