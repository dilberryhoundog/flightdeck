Three lines in the perimeter are yours to draw, not mine: what happens to the thirty existing suites, whether the manuals and the library count as parts of the system the suite proves, and how the run's own findings about flightcrew's tooling are kept apart from the suite's findings about flightcrew.

Q1 SC1 D6

The thirty tracked suites test the runner's commands with exit codes. What happens to them?

You said earlier the existing tests must keep working, and later that the suite should be built properly for the whole lot. Both can hold, but the perimeter has to say which.

Q2 SC2

Do the manuals under flightdeck/manuals/ and the documents under library/ count as parts of flightcrew the suite proves?

A manual can be checked structurally (it renders, every path it names exists, every command it quotes parses) and by artefact (the spec manuals are byte-frozen). That is real coverage but it widens 'every part' beyond the code.

Q3 SC3 D4

The run will produce two kinds of finding: what the suite learns about flightcrew, and what the run learns about flightcrew's tooling by using it. Where does each go?

Mixing them in one place is the thing that made the earlier run logs hard to mine.
