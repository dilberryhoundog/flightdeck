# Rubric · T28 · a role file a reader can carry out

**Covers** B72.

**Subject** the run-chain role files at `flightdeck/flightcrew/crew/` — explorer, planner, orchestrator, steward, interface-builder, implementer, strong-worker, adversary, verifier, critic, judge, scribe, test-builder — read each one beside its dispatch template at `flightdeck/flightcrew/templates/dispatch/<role>.template.md`. The three spec-chain files are out of scope and are not read.

**How to read** Take one role file and its template at a time and read them as the agent would: the template is everything that agent will be handed, and the role file is everything it is told. Answer for the set: an answer is `no` the moment one role file fails it, and the quote is the line that failed.

**Questions**

1. Does every input a role file tells its agent to read appear in that role's dispatch template as a slot the renderer fills, so the agent is never told to go and find something the dispatch does not carry?
2. Does every command a role file tells its agent to run fall inside the tools its own frontmatter grants, with no instruction to run a leaf, a git command or a tool the role does not hold?
3. Is every role file free of an instruction to write, edit or create a file where its frontmatter forbids writing — including indirect writes through a shell redirect or a tool its `disallowedTools` names?
4. Does each role file state what its agent returns in a form matching the fenced JSON block at its end, so a reader knows the shape it owes before it starts?
5. Reading one role file and its template alone, with no other document in hand, is every instruction one the agent could actually carry out — nothing that depends on knowing the spec text, another role's dispatch, or a document the template does not name?

**Verdict** `pass` when every answer is `yes` with a non-empty quote; `fail` otherwise. An answer of `no` names the role file and quotes the instruction that cannot be carried out.
