flightcrew-core v2 · round 2 — one bundle per problem

Clean v1, your intent verbatim, all ten problems placed. Eight bundles carry the only forks left; P1 (layout) and P6 (roster) had none and are placed without a question. The spec viewer tab shows every node.

bundle P2-json-foundation · gap · interfaces

JSON foundation and freeze. Placed: C10, C11, I4, I13, B3, B4, D5, E3.

Q1Who writes a gate clearance into launch.json?

No command a human types advances a run, and a workflow cannot write a file. The record still needs the clearance written by something.

bundle P3-runner-leaves · dual-path · scope

Runner as leaves. Placed: SC1, C3, I5, B5, B6, B7, B8, D2, E9, E10, E11, E12.

Q1The manuals still written as fc command sequences (journey, review, workflows, launch-anatomy): rewritten in this run (SC4 as drafted) or deleted and left for later?

Rewriting is units of work; deleting loses nothing the crew reads; leaving them hands false context to every role.

bundle P4-kickoff-conduct · dual-path · interfaces

Kickoff as workflow arguments. Placed: I14, C13, B9, B10, B11, B12, D6, E13.

Q1Is the workflow cut right: fc-plan → G1 → fc-contracts → G2 → fc-waves → G3 → fc-review → outcome → fc-end?

Fixes what each gate reads and which roles each script owns. The alternative merges contracts into waves so G2 disappears.

Q2Who conducts: an orchestrator session that invokes each workflow and reports at each gate, or the human invoking each workflow by name after clearing a gate?

Decides whether the orchestrator role has a job in this version and whether the human's surface is chat or the file system.

bundle P5-check-rail · gap · interfaces

Check rail and three verdicts. Placed: I15, I16, B13, B14, B15, D13, E15.

Q1The judge: a crew role dispatched with a rubric that returns the sheet (as drafted), or a leaf that shells out to a model?

C6 forbids network in scripts, so a leaf cannot call a model; a role can. The role costs a crew file and a template.

bundle P7-dispatch-returns · gap · behaviours

Dispatch and return contracts. Placed: I8, I9, B18, B19, D9, E4.

Q1Who persists a subagent's return?

A hook needs no agent cooperation and can hold the agent until the return validates; a leaf the agent calls keeps the hook set smaller but relies on the agent remembering.

bundle P8-enforcement · failure-mode · behaviours

Enforcement that fails closed. Placed: C8, C12, I6, B20, B21, B22, B23, D7, E5, E6, E7, E8.

Q1Bash held by the sandbox only, or sandbox plus a PreToolUse hook on Bash?

The sandbox cannot be talked past; a Bash hook parses commands and can be fooled but shows the agent a reason.

bundle P9-endings · gap · behaviours

Endings performed. Placed: B24, B25, B26, B27, D14, E14.

Q1An abandoned run's branch: deleted to clear the ground, or kept for its evidence?

The two source guides disagree. The draft makes it a kickoff argument (ending.abandoned_branches) with a default; this sets the default.

bundle P10-diagnosis · failure-mode · behaviours

Diagnosis reaches the next run. Placed: I10, B2 (previous_entry), B28, B29, E1.

Q1The one-change-per-retry rule: refused by flight launch run when more than one key differs, or only recorded in run.json.changed_from_previous for the human to read?

Refusing makes the discipline an instrument; recording keeps the human free to make a deliberate multi-change retry.
