Intent 1

INTstatus: ok

HITL AI engineering falls short for any large or complex task requiring a human's direct time and attention; an orchestrated agent system can solve this problem. The human front-loads their attention and time into a carefully crafted definition of the work, and beyond that an intelligently built automated system makes the work materialise through agents repeatedly attempting to discover the deterministic outcome. If the agents fail the human simply tries again, bringing the previous failures to improve the definition of the work, the tools used, or the agents' assurance of done. This orchestration toolkit is built for a single Claude Code Max subscription user, leveraging the inbuilt harness and steering infrastructure Claude provides; the product is agent-shaped. If a user's idea of a piece of work can be handed over and agents build it for them, this work has been completed.

B6status: ok

B10status: ok

Decisions 9

D1status: ok

A small command surface: core scripts callable by themselves, no dispatcher and nothing that advances a run; a flight command wrapping them is deferred to a later launch, because the first attempt's runner became the system and its tests tested the runner.

D2status: ok

Claude Code's native harness carries the conduct — agent files for roles, hooks for enforcement and recording, dynamic workflows for sequence and fan-out, the sandbox for the shell — because a mechanism the harness enforces cannot be forgotten by an agent.

D3status: ok

Every run document is JSON with a schema and every state a human owns is a field in one, because a view layer over the files is a later launch and this one fixes what it will read.

D4status: ok

The launch is the unit of work and the run the unit of attempt; a run has no phase field and no gate switch, because a run is the workflows invoked and what the human read between them.

D5status: ok

Budgets belong to the workflow runtime and the agent files; the liftoff carries the sequence, the overrides and the settings, because tooling is a failure axis and a different liftoff is cheaper than a different workflow.

D6status: ok

After the report everything is the human's — the pull request's fate, the branches, the diagnosis and the retry — because the sources put every step after the final review in the human's hands.

D7status: ok

The spec chain and its rubric are unchanged and this launch's own run-1 is hand-made, because the first carries calibration evidence and the second predates the tools that would make it.

D8status: ok

The two v1 attempt folders and RUNLOG.md stay as history, because no flightcrew run produced them and migrating them would edit frozen maps for nothing.

D9status: ok

Every guard fails closed — a guard that cannot decide refuses, a recorder that cannot record stays silent — and scripts write only inside the launch, FLIGHTLOG.md and .controlcenter, because a guard that permits by failing and a script that writes anywhere were the first attempt's two silent holes; both are proven by B32 and B5.
