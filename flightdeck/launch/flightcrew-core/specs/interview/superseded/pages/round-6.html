flightcrew-core v2 · round 6 — constraints

Stage: constraints. Five bundles, seven questions. Written this wave: C1–C3 and C8 changed; C10 every run document is JSON with a schema, C11 freeze lives in the document, C12 every guarded path is in the Bash sandbox. Facts behind this round are from the official Claude Code docs: frontmatter hooks run only while that agent acts; SubagentStop carries the agent's last message; the sandbox denyWrite reaches Bash and subprocesses; the Stop-hook cap is eight; stderr on exit 0 reaches nobody.

bundle P-scope-absorbable-commands · gap · scope

Facts from the official docs: a SubagentStop hook receives the subagent's last message, agent_id and agent_type, so a return can be captured and validated by a hook with no command; PostToolUse receives the tool input and response, so a check-after-edit can run from a role's own frontmatter hook; a workflow script has no file or shell access, so nothing a workflow does can write a document except through an agent. Proposed sorting of the built single-artefact commands follows.

Q1Does this sorting stand? ABSORBED — return → a SubagentStop hook that validates the last message against the schema for agent_type and writes runs/run-<n>/returns/; events → hooks as today; evidence page, report and log stub → the scribe role writing from the JSON documents; budget → the stop gate reading events; boundary and locked → folded into check; plan render → dropped. REMAINING LEAVES — check (runs the map's checks, writes evidence), render (one dispatch prompt per subagent role), merge (lands a unit branch), validate and lint, launch init and launch run, install (what distribute and doctor did).

This is the leaf set the interfaces stage names and the implementers build; everything absorbed is a hook or role behaviour instead.

bundle P-constraints-role-reach · gap · constraints

Explored. Official docs: a role's tools, disallowedTools, permissionMode, isolation and hooks are frontmatter fields and govern only that agent; frontmatter hooks run only while that agent acts; settings permissions are global, and Agent(name) there is a deny or allow of dispatching that role; Edit/Write denies do not reach subprocess writes, the sandbox denyWrite does.

Q1Given those facts, is a role's reach declared like this: the role file is the single source for what the role can do (tools, mode, isolation, its own hooks); settings hold only what no role can express — the sandbox denyWrite list, global recording hooks, and the list of roles a session may dispatch — and the install leaf derives that dispatch list from the crew folder?

Closes the two-files-that-contradict hole. The alternative keeps two hand-written files and adds a check.

bundle P-behaviours-enforcement-fails-closed · failure-mode · behaviours

Constraints-facing part only. C8 now says a guard that cannot decide denies and a recorder stays silent, and C12 puts every guarded path in the sandbox denyWrite. Two forks remain that only you can settle.

Q1How is Bash held to the locked and frozen paths?

The sandbox is the mechanism the docs say cannot be talked past; a Bash PreToolUse hook parses commands and can be fooled. Both is belt and braces at the cost of a second mechanism to keep in step.

Q2Which phases carry an end-of-turn gate?

v1 gated contracts and verify only; implement, where roles hold write access, had none. A gate in every writing phase is the constitution's floor; each gate needs a check to run.

Q3When the stop gate reaches its eighth block and Claude Code overrides it, what does the run do?

stderr on exit 0 reaches nobody. A stall must be visible to the session and must stop the run without the guards silently denying everything after.

bundle P-interfaces-json-document-foundation · gap · interfaces

Constraints-facing part only: C10 makes every run document JSON with a schema and C11 puts freeze in the document. One fork is a constraint on who may write phase state, and a workflow script cannot write a file at all.

Q1Who writes a phase change and a gate approval into the launch record?

No command a human types advances a run. Something still has to write the record; the options differ in whether an agent ever writes phase state.

bundle P-scope-pilot-rename · gap · scope

pilot is a boolean on a plan unit: the one or two representative units a wave runs first, the rest starting on their green. No role is named pilot anywhere in the tree.

Q1What is renamed to scout?

A unit flag renamed is a schema field and a planner rule; a role named scout would be a new crew file whose job you would need to state.
